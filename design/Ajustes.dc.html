nodo sistema / ajustes ./zeruel.toml
Gana el mas especifico: flag de CLI › variable de entorno › zeruel.toml › default. Cada opcion dice de donde salio su valor actual, y lo que hoy esta pisado por un flag no se deja editar desde aca.
Ejecucion
Runs en paralelo
scheduler.max_runs
Cuantos procesos de pipeline puede haber a la vez. El control de admision ademas frena por RAM disponible.
pisado por --max-runs
Techo de RAM por run
scheduler.ram_max
El run se corta si lo pasa. Se aplica ademas un tope duro del sistema operativo un 12% mas arriba, para la reserva de golpe que el muestreo no llega a ver.
zeruel.toml
Tick del scheduler
scheduler.tick_ms
Cada cuanto revisa cron y cola. Con runs vivos baja solo a 250 ms para reaccionar rapido a una cancelacion.
default
Timeout por run
scheduler.timeout_min
Se mata el proceso y el run queda como fallido. Sin esto, un pipeline colgado ocupa un lugar para siempre.
zeruel.toml
Retencion lo que decide cuanto crece el disco
Detalle por tarea
gc.detalle_dias
RAM y CPU de cada tarea de cada run. Es lo que mas pesa y lo que menos se mira pasada una semana.
default
Runs
gc.runs_dias
La fila del run sin su detalle: estado, duracion, filas.
default
Agregados mensuales
gc.rollups
Ocupan poco y son lo unico que permite comparar contra el año pasado.
default
Logs de runs
gc.logs_dias
El stdout y stderr de cada proceso.
zeruel.toml
Acceso
Sin token, zeruel web escucha solo en 127.0.0.1 y no pide nada. En cuanto se expone a la red, el token pasa a ser obligatorio.
escucha en127.0.0.1:9876
token${ZERUEL_TOKEN}
definidosi, por entorno
El toml guarda el nombre de la variable, no su contenido: asi se puede versionar sin que el secreto entre al repositorio.
zeruel.toml como queda
[scheduler] max_runs = 4 ram_max = "2G" timeout_min = 60 [gc] logs_dias = 14 [web] token = "${ZERUEL_TOKEN}"
Solo se escribe lo que difiere del default. Un archivo con las 20 opciones repetidas esconde las 4 que alguien cambio a proposito.
Claves desconocidas
Una clave que no existe hace fallar el arranque con el nombre exacto, en vez de ignorarse.
Un max_run mal escrito que se ignora en silencio deja el sistema con el default y a alguien convencido de que lo cambio.
